# legacy —— 经过真机验证的旧版脚本（备用）

这里的两个脚本是在真实站点上**从头跑通过一整本书**（415 页）的版本，
保留它们是因为 `frontend/grabber.js` 的「直取模式」目前只在 mock 环境里验证过，
还没在真实站点上跑过。万一新版在真机上出问题，可以退回这两个。

| 文件 | 作用 |
|---|---|
| `scroll-harvest.js` | 滚动采集版：一边滚阅读器一边从网络记录里收页，推给 collector |
| `page-repair.js` | 补页版：按已知图片前缀直取指定页号，补齐滚动时被跳过的页 |

## 用法

后端（`backend/collector.py`）保持运行，把脚本粘进阅读器页面的 Console 即可。
两者的书标识算法与 `frontend/grabber.js` 一致，落盘到同一个目录，所以可以混用、
也可以互相补页。

## 注意

- `scroll-harvest.js` 靠滚动加载，慢（约 3~4 分钟/本）且**可能漏页**（每步滚 1.15 屏，
  个别页会卡在两次滚动之间）。跑完建议用 `page-repair.js` 或直接看有没有断号。
- 两个脚本都假设图片前缀对整本书固定 —— 这一点已在真实站点上验证过。
